# SSWCenter 최소기능 재정렬 활성 테스트 매트릭스

> 기준일: 2026-08-12 KST
> 지위: `docs/06_개발로드맵_결정현황_v1.2.md`가 지정하는 활성 실행 명세
> 비지위: 제품 정본, 현재 SHA, 실행결과, 담당자 기록이 아님

## 0. 사용 원칙

- 제품 의미는 정본 01~06이 소유하고 이 문서는 그 의미를 검증하는 ID와 기대결과만 소유한다.
- 옛 테스트가 통과해도 최신 정본과 충돌하면 옛 테스트를 고치거나 폐기한다.
- 테스트를 쉽게 만들기 위해 상태·테이블·FK·화면·연동을 추가하지 않는다.
- 각 slice는 필요한 DB·API·OpenAPI·생성 타입·UI·실제 PostgreSQL·브라우저 검증을 같은 후보에서 통과한다.
- 가짜 숫자·하드코딩 목록·CSS 문자열 존재만으로 기능 PASS를 주지 않는다.
- mutation-sensitive assertion이 실제 규칙을 깨뜨렸을 때 실패하는지 확인한다.
- `UNKNOWN` 항목은 사용자 결정이나 실제 표본 전까지 PASS 기대값을 만들지 않는다.

## 1. 공통 판정

| 결과 | 의미 |
|---|---|
| `PASS` | 지정 범위의 정본·코드·실행 증거가 모두 일치하고 미검증 필수항목이 없음 |
| `FAIL` | 구현 또는 실행결과가 확정 계약과 다름 |
| `BLOCKED` | 해당 slice에 필요한 사용자 결정·실제 표본·환경이 없어 검증 불가 |
| `HARNESS_FAILURE` | runner·fixture·환경 문제로 제품 판정 자체를 만들 수 없음 |

부분 PASS를 전체 PASS로 올리지 않는다. 정적 PASS는 실제 PostgreSQL·브라우저 PASS를 대신하지 않는다.

## 2. 유지할 공통 안전장치

| ID | 계약 | 최소 증거 |
|---|---|---|
| `CMN-01` | PIN·세션·CSRF | 6자리 PIN, hash/HMAC, CSRF, 세션만료, 계정전환 stale 응답 차단 |
| `CMN-02` | 낙관적 잠금 | 변경 API의 `row_version`, 409, 사용자 입력 보존 |
| `CMN-03` | 감사 | 변경 전후·행위자·시각, 민감값 비기록, 실패 rollback |
| `CMN-04` | 개인정보 | 주민번호 평문 비노출, reveal·정정 보호, 로그·fixture leak 부재 |
| `CMN-05` | PostgreSQL | fresh upgrade, catalog·FK·CHECK·trigger·ACL, downgrade/restore 범위 |
| `CMN-06` | OpenAPI·타입 | 공개 route/schema와 생성 TypeScript drift 없음 |
| `CMN-07` | UI 접근성 | 실제 control, keyboard/label, loading/error/empty, 계정전환 purge |
| `CMN-08` | 백업·복원 | DB와 필요한 파일을 같은 복구단위로 복원하고 fingerprint 일치 |

## 11. 명시적 DEFER / OUT-OF-SCOPE

이번 S0~S6 재정렬 때문에 다음 메뉴·기능을 삭제하거나 새 의미로 확정하지 않는다.

- 본인부담금·수가·청구·수납
- OCR
- 별도 입출력 기능
- 공식 출력
- 승인된 USB·외장 SSD 역할 안의 실제 장치 ID·경로·세대수·책임자(운영 도입 때 별도 승인하며 현재 활성 register에는 넣지 않음)

해당 기존 안전기반은 보존하며 별도 승인된 slice 전에는 구현을 확장하지 않는다.

## 14. slice 공통 종료조건

각 slice는 다음을 모두 만족해야 닫을 수 있다.

1. 정본 anchor와 실제 변경경로가 일치한다.
2. allowlist 밖 사용자 변경을 덮어쓰지 않았다.
3. migration은 새 forward revision이고 기존 적용 migration을 수정하지 않았다.
4. API·OpenAPI·생성 타입·UI가 같은 계약이다.
5. 실제 PostgreSQL mutation·rollback·동시성·ACL을 검증했다.
6. 실제 브라우저에서 control·값·권한·계정전환을 검증했다.
7. 금지 구조 부재를 코드·OpenAPI·DOM·catalog에서 검사했다.
8. 실패 시 제품결함과 harness 문제를 구분했다.
9. dirty 상태·changed paths·미검증 항목을 숨기지 않았다.
10. 독립 검수자가 같은 후보 bytes를 다시 판정했다.
