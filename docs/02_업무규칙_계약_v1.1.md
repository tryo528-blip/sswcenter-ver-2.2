# SSWCenter v2.2-alpha 업무규칙 계약 v1.1

> 기준일: 2026-08-12 KST
> 지위: 직원·수급자·완료현황·일정·사회복지사 업무의미 단일 정본
> 대체: `02_새프로젝트_기능요구사항_정리본_v1.0.md`

## 0. 문서 적용 원칙

이 문서는 SSWCenter ERP의 현재 활성 업무계약이다. 국민건강보험공단 전산을
대체하지 않고, 평가 대상·기관 일정·사회복지사 업무를 놓치지 않게 하는 데
필요한 최소 규칙만 정의한다. 판단순서와 현재 정본 목록은
[00 정본 목록](00_정본_문서_목록.md)을 따른다. 과거 branch·구현·검수보고서는
비교 증거이며 현재 업무계약을 바꾸지 않는다.

이 문서의 변경은 제품 코드나 DB를 자동 변경하지 않는다. 구현은 별도 작업단위와
마이그레이션·API·UI·테스트 승인을 거친다.

## 1. 현재 결정 적용

현재 확정 업무계약의 본문은 이 문서의 해당 영역 절에만 둔다. 제품 목적은
평가 대상·완료현황, 수급자–요양보호사 일정, 사회복지사 업무흐름 세 축이다.
공단이 이미 검증하는 계약·인정 적합성이나 계획 적용기간을 이 ERP에서 다시
판정하지 않는다.

폐기된 비교안과 결정 이유는 Git·`review/` 이력으로 보존한다. 활성 입력·화면·
API에서는 제거하되 기존 사실·감사·마이그레이션 이력을 임의 삭제하지 않는다.
현재 계약에서 금지한 구조는 nullable·deprecated·숨김 필드로 우회하여 만들지
않고, 미래 필요만으로 호환 컬럼이나 nullable FK를 추가하지 않는다.

## 2. 구현 경계

전체 범위와 S0·R0·S1~S6 경계의 단일 원문은
[`01_목적_범위_추진원칙_v1.5.md`](01_목적_범위_추진원칙_v1.5.md)다.
이 문서는 각 업무규칙만 정의한다.

기존 `Staff`, `StaffEmployment`, `StaffPositionPeriod`,
`StaffOperationalRolePeriod`, `BusinessNumberCounter`를 확장하며 같은 의미의
모델을 중복 생성하지 않는다. `staff.display_name`과 `staff.memo`도 별도 승인된
폐기 결정 없이 삭제·병합하지 않는다. 현재 단계가 사용하지 않는 카드·일정·
실행·파일 모델을 미래 필요만으로 미리 만들지 않는다.

## 3. 직원

<a id="fr-staff-core"></a>

### 3.1 직원과 재직

- 내부 직원 ID와 재직번호를 분리한다.
- 재직기간은 같은 직원 안에서 서로 겹치지 않는다.
- 퇴사상태는 재직기간 종료일로 계산하고 별도 근무상태를 이관하지 않는다.
- 재입사는 기존 직원에 새 재직기간과 새 재직번호를 생성한다.
- 재직번호 발급은 기존 transaction-safe 번호 카운터를 확장한다.
- 직종과 시스템 업무역할을 분리한다.
- 직종·역할·서비스 제공자격 기간은 해당 재직기간 안에 있어야 한다.
- 재직 범위 자식원장은 `(staff_id, employment_id)` 복합 FK로 같은 직원의
  재직기간만 참조하게 한다.
- 직원 명단·기본정보는 로그인 사용자 모두가 조회하고 전화·주소·메모 등 일반
  필드를 수정할 수 있으며 변경을 audit한다. 주민등록번호는 §3.2의 강화 보안
  명령으로만 다룬다.
- 재직 중 직종을 바꾸는 일반 변경화면은 만들지 않는다. 사회복지사와
  요양보호사처럼 직종이 바뀌면 기존 재직을 종료하고 새 재직으로 재입사한다.

### 3.2 민감정보와 연락처

- 기존 직원과 bootstrap 직원은 민감정보 행이 0개 또는 1개일 수 있다.
  일반 직원 신규등록은 주민등록번호를 필수로 받아 직원과 민감정보
  행을 한 transaction에서 생성한다.
- 입력은 숫자 13자리 또는 `YYMMDD-XXXXXXX` 형식만 허용한다. 저장 전 하이픈을
  제거해 숫자 13자리로 정규화한다.
- 앞 6자리의 실제 달력날짜와 일곱 번째 숫자의 세기·성별이 `birth_date`와
  `sex_code`에 일치해야 한다. 일곱 번째 숫자 `9/0`은 1800년대,
  `1/2/5/6`은 1900년대, `3/4/7/8`은 2000년대이며 홀수는 남성, 짝수는
  여성으로 판정한다. legacy 호환을 위해 주민번호 checksum 불일치만으로는
  거부하지 않는다.
- 일반 화면의 마스크는 복호화하지 않고 `birth_date`에서
  `YYMMDD-*******`로 만든다.
- 전체번호는 일반 목록·상세·검색·기본 내보내기에 노출하지 않고 관리자
  명시 reveal에서만 일시 제공한다.
- 일반 직원 수정 명령과 수정화면에는 주민등록번호 필드를 넣지 않는다. 필드
  부재는 기존 번호 유지이며 빈 문자열로 삭제·대체할 수 없다. 상세 응답도
  평문을 form default로 돌려주지 않는다.
- 주민등록번호 오등록 정정은 일반 직원 수정과 분리된 HIGH 명령이어야 한다.
  같은 직원의 번호 교체는 현재 PIN·정정사유·`row_version`·전역 중복검사·
  단일 transaction·감사를 요구한다. 다른 직원 사이의 번호 이전이나 직원
  합치기는 별도 정책이 확정되기 전까지 차단한다.
- 초기이관은 안정 legacy mapping으로 같은 사람임이 확정된 행에 한해 같은
  transaction에서 민감정보를 교체할 수 있다. 이름·전화 같은 추정 일치만으로
  교체하지 않는다.
- DB 컬럼·길이·unique 불변조건은
  [`04` `db-staff-sensitive`](04_데이터_DB_불변조건_v4.8_PostgreSQL.md#db-staff-sensitive), 암호화·key·
  reveal·rotation·평문 금지 protocol은
  [`05` §5.5](05_기술_보안_파일처리_아키텍처_v1.5.md#resident-security), 화면/DOM은
  [`03` §1.3·§3.2](03_UI_API_상호작용_계약_v1.2.md)를 따른다.
- 직원 전화는 화면용 원문과 결정적 정규화 projection을 분리한다.
- 전화 정규화 v1은 한국 번호만 수용한다. 바깥 공백을 제거한 원문은 화면용으로
  보존하고, 공백·하이픈·마침표·괄호만 구분자로 제거한다.
- 파싱은 국제형을 먼저 판정한다. `+82` 또는 `0082` 다음의 선행 `0` 없는
  숫자 8~10자리를 국제형으로 처리한 뒤, `0`으로 시작하는 숫자 9~11자리를
  국내형으로 판정한다.
- 정규화값은 국내 선행 `0`을 제거한 `+82`와 나머지 숫자의 결합이다. 예를 들어
  `010-1234-5678`, `+82 10 1234 5678`, `0082-10-1234-5678`은 모두
  `+821012345678`이다.
- 빈 입력은 원문·정규화값 모두 `NULL`로 만들고, 다른 국가코드·내선·문자·길이
  오류는 422로 거부한다. 정규화값은 unique 식별자가 아니며 일반 응답에는
  기본 노출하지 않는다.
- 정규화 projection은 실제 태그 Excel 표본에서 전화번호 매칭 필요가 확인된
  경우에만 정확 일치 보조키로 사용할 수 있다. 표본 확인 전에는 식별자로
  확정하지 않는다.

### 3.3 자격·교육·검진·상담

#### 3.3.1 자격증·서비스 제공자격

일반 자격증 사실과 서비스 제공자격 기간은 서로 다른 원장이다.

- `license_type`은 자격종류 코드·표시명을 관리한다. 최초 seed는 다음 3개로
  고정한다.

| code | 표시명 |
|---|---|
| `CARE_WORKER` | 요양보호사 |
| `SOCIAL_WORKER` | 사회복지사 |
| `NURSE` | 간호사 |

- 위 code는 기존 사실이 참조하는 안정 catalog code이므로 일반 업무에서
  변경·삭제하지 않는다. 최초 seed에 등급 구분, 간호조무사, 관리책임자,
  관리책임자(시설장)를 넣지 않는다. 새 자격종류가 필요하면 기존 code의 의미를
  바꾸지 않고 사용자 결정 뒤 새 row를 추가한다.
- `staff_license`는 직원·자격종류·자격번호·발급일을 관리한다. 자격증 유효
  시작일·종료일·만료일은 만들지 않으며, 일반 CRUD는 3개 이상을 허용한다.
- 초기등록 workbook의 자격 2개는 입력범위일 뿐 일반 원장의 최대 개수가 아니다.
- `staff_service_qualification_period`는 재직기간별 서비스 제공 가능 기간의
  안정 ID를 제공한다. 직원·재직·서비스종류·시작일·선택 종료일을 가지며
  선택 `source_license_id`로 같은 직원의 자격증 사실을 근거로 연결할 수 있다.
- 자격증만 보유하고 서비스 제공자격 기간이 없는 상태와, 한 자격증을 재입사한
  여러 재직의 제공자격 근거로 다시 사용하는 상태를 모두 허용한다.
- 서비스 제공자격 기간은 자격증 유효기간이 아니며 해당 재직기간 안에 완전히
  포함되어야 한다. 재직기간 단축·무효화의 역방향 검사도 같은 불변조건을
  보장하고, 부모·자식을 한 transaction에서 함께 정정하는 것은 허용한다.
- 일반 자격증 CRUD와 서비스 제공자격 기간 CRUD는 API·OpenAPI·UI 탭·오류코드를
  분리한다. 자격증 삭제가 아니라 무효화/대체를 사용하며, 근거 자격증을
  무효화해도 제공자격 기간을 자동종료하지 않고 명시적 정정 절차를 거친다.

#### 3.3.2 교육

교육 seed는 다음 8개로 고정한다.

| code | 표시명 | cycle |
|---|---|---|
| `NEW_HIRE_ORIENTATION` | 신규직원교육 | `ON_HIRE` |
| `ELDER_RIGHTS` | 노인인권 | `HALF_YEAR` |
| `DISABLED_ABUSE` | 장애인학대 신고의무자교육 | `ANNUAL` |
| `ELDER_ABUSE` | 노인학대 신고의무자교육 | `ANNUAL` |
| `SEXUAL_HARASSMENT` | 직장 내 성희롱 예방교육 | `ANNUAL` |
| `WORKPLACE_BULLYING` | 직장 내 괴롭힘 예방교육 | `ANNUAL` |
| `PRIVACY` | 개인정보보호교육 | `ANNUAL` |
| `CONTINUING_EDUCATION` | 보수교육 | `BIENNIAL` |

- 직원 완료현황은 보수교육, 직원상담, 인권교육, 연간교육, 건강검진,
  신규교육 6종을 탭 또는 동일 수준의 구분으로 제공한다.
- 교육시간·이수일자·이수센터·수료증/file FK·면제사유·미완료사유를 새 활성
  입력으로 만들지 않는다.
- 신규교육, 보수교육, 직원상담, 인권교육, 연간교육은 `완료`와 `완료 취소`
  버튼으로 처리한다. 체크박스를 사용하지 않으며 매 변경의 행위자·시각·전후값을
  audit한다.

대상 산정은 다음과 같다.

1. **신규교육**은 재직기간별 1건이다. 최초 입사와 재입사마다 새 미완료 대상을
   만들고 이전 재직의 완료를 재사용하지 않는다. 퇴사해도 그 재직의 과거 대상과
   완료 이력은 남는다.
2. **보수교육**은 조회시점 현재 재직 중인 요양보호사 중 대상연도와 출생연도의
   홀짝이 같고, `대상연도 - 최초 요양보호사 자격 취득연도 > 2`인 직원을
   대상으로 한다. 최초 요양보호사 자격 취득연도를 확인할 수 없으면 임의 면제하거나
   완료하지 않고 `확인요망`으로 표시한다.
3. **인권교육**은 선택 반기 마지막 날에 재직 중인 직원을 대상으로 한다. 반기
   중간 입사자는 마지막 날 재직 중이면 포함하고, 마지막 날 전 퇴사자는 제외하며,
   마지막 날 퇴사자는 포함한다. 같은 반기 안의 재입사는 같은 완료상태를 공유한다.
4. **연간교육**은 선택연도 12월 31일에 재직 중인 직원을 대상으로 한다. 종료일이
   12월 31일이면 포함한다. 같은 연도 안의 재입사는 같은 완료상태를 공유한다.
   `DISABLED_ABUSE`, `ELDER_ABUSE`, `SEXUAL_HARASSMENT`,
   `WORKPLACE_BULLYING`, `PRIVACY` 5과목이 모두 완료되어야 연간교육 완료다.

#### 3.3.3 건강검진

건강검진의 새 활성 입력은 직원별 **검진일** 하나뿐이다. 검진유형, 결과메모,
면제상태·면제사유, 증빙/file FK를 새 화면이나 변경 API에 두지 않는다. 기존
상세 검진 자료가 있으면 이력으로 보존하되 새 완료현황의 진실값으로 확장하지
않는다.

- 선택연도에 새로 입사한 직원은 그 해 중 퇴사했어도 대상이다.
- 선택연도보다 먼저 입사한 직원은 그 해 12월 31일에 재직 중일 때 대상이다.
  종료일이 12월 31일이면 포함한다.
- 검진일이 있으면 완료, 비어 있으면 미완료다. 건강검진은 완료 버튼이 아니라
  검진일 입력·정정·삭제로 상태가 바뀐다.
- 선택연도 신규직원의 검진일이 입사일보다 **1달력년을 초과하여 이전**이면
  주의표시한다. 정확히 1달력년 이전은 주의 대상이 아니다.
- 검진일 변경은 행위자·시각·전후값을 audit한다.

<a id="fr-staff-quarterly"></a>

#### 3.3.4 직원 분기상담

직원상담은 직원·달력연도·분기별 완료현황이다.

- 선택 분기의 첫날부터 마지막 날까지 전 기간 재직한 요양보호사를 대상으로 한다.
  분기 첫날 입사와 분기 마지막 날 퇴사는 포함한다.
- 기본 화면은 현재 분기를 연다.
- 화면은 대상 직원과 완료/미완료만 보여준다. 상담일, 상담내용, 미완료사유,
  면제사유, 증빙/file FK를 새 활성 입력으로 만들지 않는다.
- 완료와 완료 취소를 audit한다.
- 이 완료현황은 실제 급여제공 순서로 판정하는 직원교체 업무와 별개다.

<a id="fr-staff-legacy"></a>

### 3.4 legacy 직원 mapping

- legacy 직원키는 별도 내부 mapping 원장에 둔다.
- 일반 직원 API·OpenAPI·UI·검색·출력에는 노출하지 않는다.
- 구 시스템 별칭·고용형태·계좌·급여·보험·퇴직금·서비스단가·미사용 컬럼과
  과거 건강검진 자료를 초기 이관하지 않는다.

<a id="fr-recipient"></a>

## 4. 수급자·보호자·납부자

### 4.1 수급자

필수값은 이름·생년월일·성별뿐이다. 우편번호·주소·자택전화·휴대전화는
선택이며 자택전화와 휴대전화를 분리한다.

- 내부 PK와 화면 수급자번호를 분리한다.
- 수급자번호는 최초 계약 확정 시 transaction-safe하게 한 번 발급한다.
- 최초 계약 전 수급자 등록을 허용한다.
- 재계약·서비스 추가에도 같은 수급자번호를 유지한다.
- 구 등록번호를 새 수급자번호나 주민등록번호로 해석하지 않는다.
- `legacy_recipient_key`, `legacy_attachment_key`는 별도 내부 mapping에만 둔다.
- 질병정보와 기존 비고는 출처를 표시하여 수급자 메모에 합친다.
- 수급자 명단·기본정보는 로그인 사용자 모두가 조회·수정할 수 있고 변경을
  audit한다. 민감정보 원문은 별도 강화 보안계약을 따른다.
- 계약 종료일 입력과 수급자 현재상태의 `계약종료` 전환은 서로 다른 수동
  행위다. 한쪽이 다른 쪽을 자동 변경하지 않는다.

### 4.2 보호자

- 수급자당 0명 이상이다.
- 이름만 필수이며 전화번호·주소·관계는 선택이다.
- 대표 보호자는 없어도 된다.
- 같은 시점의 대표 보호자는 최대 1명이며 변경 이력을 보존한다.
- 생년월일·성별을 신규 Clean 스키마·API·UI에 만들지 않는다.

### 4.3 독립 납부자 snapshot

- 수급자당 현재 0명 또는 1명이다.
- 행이 있으면 이름만 필수이고 전화번호·주소·관계는 선택이다.
- 보호자와 FK로 연결하지 않는다.
- 본인 납부도 payer type으로 표현하지 않는다.
- 보호자 변경은 납부자 snapshot을 자동변경하지 않는다.
- 본인부담금 상세설계를 재개할 때 청구 개정본은 당시 납부자 snapshot을 복사한다.
- 화면의 `보호자를 납부자로 지정` 선택은 프로젝트 전반의 체크박스 금지에 대한
  명시적 예외다.

### 4.4 계약서명자 snapshot

계약서명자 이름·관계·전화번호는 새 활성 계약 입력·응답·목록에서 사용하지
않는다. 기존 값이 있으면 계약 당시의 역사 자료로 보존하되 보호자·납부자 FK를
새로 만들거나 새 완료·검증 규칙의 근거로 사용하지 않는다.

<a id="fr-certification"></a>

## 5. 인정·등급·혜택·승인금액

### 5.1 인정 본번호와 기간

- 입력은 `L + 숫자 10자리`이며 소문자 입력은 대문자 `L`로 정규화한다.
- `-100`, `-101`, `-102` 등의 suffix를 제거하고 본번호만 저장한다.
- 한 수급자는 본번호 1개만 소유한다.
- 같은 본번호를 다른 수급자에게 연결하지 않는다.
- 인정 발급일은 신규 필수값이 아니다.
- 같은 수급자의 유효 인정기간은 서로 겹치지 않는다.
- 과거 기간과 무효화·대체 이력을 보존한다.

### 5.2 등급

- 허용 등급은 `1`, `2`, `3`, `4`, `5`뿐이다.
- 인지지원등급과 자유코드를 허용하지 않는다.
- 등급은 유효 시작일·종료일 기간으로 저장한다.
- 별도 등급변경일 컬럼을 만들지 않는다.
- 등급기간은 해당 인정기간 안에 있고 서로 겹치지 않는다.

### 5.3 혜택

고정 코드:

```text
GENERAL
BASIC_LIVELIHOOD
REDUCTION_6
REDUCTION_9
MEDICAL_6
MEDICAL_9
```

- 시작일은 월초가 아니어도 된다.
- 같은 수급자의 유효 혜택기간은 코드와 무관하게 서로 겹치지 않는다.
- 자료가 없다고 `GENERAL`을 자동생성하지 않는다.
- 부담률 수치는 본인부담금 상세설계를 재개할 때 공식 규칙버전에서 확정한다.
- 현재 원장은 서비스 제공일 기준 혜택을 찾을 수 있는 기간사실을 제공한다.
- 서비스 제공일에 적용되는 혜택기간이 없는 경우의 부담률 처리는 자동 기본값을
  갖지 않으며, 본인부담금 상세설계가 재개되기 전에는 `GENERAL`로 간주하지 않는다.

### 5.4 지자체 승인 월급여액

- 혜택과 독립된 기간원장이다.
- 수급자·승인금액·시작일·종료일·무효화/대체 이력을 가진다.
- 금액은 원 단위 bigint이다.
- 같은 수급자의 유효 승인금액 기간은 서로 겹치지 않는다.
- 월중 최고금액 적용 계산은 본인부담금 상세설계가 재개되기 전에는 계산하지 않는다.

## 6. 인정전환 실행기능 퇴역

등급조정·새 인정기간 전환을 한 번에 preview/apply하는 실행기능은 활성 제품에서
제거한다. 공단이 이미 판단한 인정과 계약의 적합성을 ERP가 다시 검증하거나
관련 행을 일괄 종료·대체하지 않는다.

- 인정·등급·계약은 각각의 일반 입력·정정 경로에서 사람이 기록한다.
- 인정전환 전용 API·OpenAPI·UI·생성 타입·실행 테스트는 제거 대상이다.
- 기존 인정·등급·계약·감사 행과 과거 실행 결과는 임의 삭제하거나 새 규칙으로
  다시 쓰지 않는다.
- 이미 적용된 migration은 수정하지 않는다. 구체적인 퇴역은 새 forward
  migration과 별도 R0 작업단위로 수행한다.

## 7. 서비스 계약

방문요양, 방문목욕, 일시재가, 병원동행, 바로돌봄 5종을 모두 사용한다.

- 새 활성 계약 입력은 서비스 종류, 시작일, 선택 종료일, 선택 자유입력 종료사유다.
- 급여개시일과 계약서명자 이름·관계·전화번호는 새 입력·변경·응답·목록에서
  사용하지 않는다. 기존 값은 감사·이관 결정 전까지 역사 자료로 보존한다.
- ERP는 공단이 이미 확인한 계약·인정 적합성, 서비스 조합, 기간 중첩을 다시
  검증하지 않는다.
- 종료사유는 자유입력·빈 값 허용이며 고정 코드로 제한하지 않는다.
- 별도 퇴소일을 만들지 않는다.
- 종료된 계약은 재활성화하지 않고 재이용 시 새 계약을 만든다.
- `contract_no`는 기본 Clean 스키마에 만들지 않는다.
- 향후 계약번호가 필요하면 별도 사용자 승인 뒤 nullable 외부참조로 추가한다.
- 계약 종료일 입력과 수급자 상태의 `계약종료` 전환은 각각 사람이 수행한다.
  한쪽이 다른 쪽을 자동 변경하지 않는다.

## 8. 배정

### 8.1 요양보호사 배정과 계획일정

기존 요양보호사 기간배정 자료는 역사로 보존할 수 있으나 새 계획일정의 필수
FK나 저장 차단조건으로 사용하지 않는다. 일정의 요양보호사 변경은 일반 일정
수정이며, 배정변경만으로 직원교체 업무를 만들지 않는다.

### 8.2 사회복지사 담당 수급자 연결

- 사회복지사를 선택하면 그 사람의 담당 수급자 목록과 방문일정을 표시한다.
- 별도의 `담당 사회복지사` 입력란을 각 방문일정에 반복하지 않고 선택한 사람의
  담당연결을 사용한다.
- 로그인 사용자 모두가 모든 사회복지사의 담당 수급자 연결을 조회·생성·변경·
  해제할 수 있고 변경을 audit한다.
- 간호사는 직원 직종 표시만 간호사이며 사회복지사와 같은 사용자·달력 흐름을
  사용한다. 간호사 전용 탭, 별도 간호사 담당배정 차원, 역할별 권한을 만들지 않는다.

## 9. 수급자 완료현황 5종

수급자 완료현황은 로그인 사용자 모두가 조회하고 완료를 처리할 수 있다. 화면은
대상 수급자와 완료/미완료를 기본으로 보여주며 발생 이유, 기준일, 기한,
완료자·완료시각, 상세화면 링크, 일정표 링크를 추가하지 않는다. 완료 가능한
항목은 `완료`와 `완료 취소` 버튼으로 처리하고 체크박스를 사용하지 않는다.
변경의 행위자·시각·전후값은 audit에만 남긴다.

### 9.1 상담반영

- 선택연도 수급자별 1회다.
- 선택연도 중도 계약종료자는 대상에서 제외한다.
- 대상자 필터와 완료/미완료만 관리한다. 상담내용, 반영내용, 면제사유를 새
  활성 입력으로 만들지 않는다.

### 9.2 반기평가

반기평가는 별도 계약서 작성·검증 기능이 아니라 **급여계획 통보를 반기에 한 번
놓치지 않았는지 확인하는 완료현황**이다.

- 유효한 `recipient_plan_notification.notified_date`만 완료 증거다. 별도 완료
  boolean이나 완료 버튼을 만들지 않는다.
- 마지막 유효 통보일이 있으면 기본 기한은 그 날짜에서 6개월 뒤가 속한 달의
  말일이다. 현재 유효 인정종료일과 계약종료일 중 더 이른 알려진 날짜로 cap한다.
- 자동카드는 실제 기한 D-45에 시작하고 달력에는 실제 기한 날짜에 표시한다.
- 유효 통보 이력이 없으면 미완료로 보여주되 기한·D-day를 지어내지 않고
  달력에도 배치하지 않는다. 사용자가 과거 통보일을 입력하면 그 사실로 다시
  계산한다.
- 통보 사실을 무효화하면 완료도 취소된다.
- 계획 적용 시작일·종료일 텍스트가 남아 있어도 날짜로 해석·비교·저장차단·
  업무기한 계산에 사용하지 않는다.
- 옛 W2 `recipient_service_plan_notice` 테이블과 연결 계약·인정 검증,
  insert/update/sequence 실행
  경로는 R0 퇴역 대상이다. 기존 행·PK/FK·조회·감사·마이그레이션 이력은
  명시적 이관 전까지 보존하고, `recipient_plan_notification`은 활성 원장으로
  유지한다.

### 9.3 서류미비

- 선택월에 수급자–요양보호사 서비스 일정이 1건 이상 있는 모든 수급자를 그
  수급자–월 단위 대상으로
  한다.
- 일정이 있는 모든 월은 서로 독립된 완료현황이다.
- 서류 종류, 누락 사유, 첨부파일을 새 필수 필드로 만들지 않는다.
- 여기서 일정은 사회복지사 방문·연차·개인일정이 아니라 §12의 수급자–요양보호사
  서비스 일정이다. 완료원장은 S2에서 준비할 수 있지만 대상자 projection과
  수용검사는 S4 `service_schedule` 원장·수동 CRUD 뒤에 닫는다.

### 9.4 인정만료

- 현재 유효하고 대체되지 않은 인정기간이 종료일 D-100에 들어오면 인정기간별
  대상으로 표시한다.
- 만료일이 지나도 완료하기 전까지 미완료 대상에서 사라지지 않는다.

### 9.5 계약만료

- 현재 유효하고 대체되지 않은 서비스계약이 종료일 D-45에 들어오면 계약별
  대상으로 표시한다.
- 만료일이 지나도 완료하기 전까지 미완료 대상에서 사라지지 않는다.

## 10. 자동 업무카드

현재 확정된 자동카드는 계약만료, 인정만료, 반기평가, 직원교체 네 종류다.

- 카드는 각 원천사실과 완료현황의 projection이다. 같은 완료사실을 범용 카드
  테이블에 다시 저장하지 않는다.
- 카드 표시는 대상자, 업무명, 실제 기한 또는 D-day, 완료 여부만 사용한다.
  발생 이유, 담당자, 단계, 처리내용, 첨부, 상세 링크와 다중 상태를 만들지 않는다.
- 계약만료는 D-45, 인정만료는 D-100, 반기평가는 D-45에 활성화한다.
  직원교체는 §14의 새 교체가 판정될 때 활성화한다.
- 계약만료·인정만료·직원교체 카드는 각 완료원장의 `완료`·`완료 취소` 버튼을
  그대로 사용한다. 반기평가 카드는 완료 버튼 대신 실제 통보일 입력·무효화만
  사용한다. 어느 카드에도 완료 checkbox를 두지 않는다.
- 기한이 지나도 미완료 카드는 계속 남는다. 완료되면 활성목록에서 빠지되
  완료이력과 달력의 완료표시는 보존한다.
- 달력 표시는 카드 노출 시작일이 아니라 **실제 기한 날짜**에 둔다. 달력에서
  직접 완료하지 않고 원천 완료가 바뀌면 달력도 같은 상태를 보여준다.
- 유효 통보일이 없는 반기평가 카드는 기한·D-day 없이 미완료로 표시하고
  달력에는 표시하지 않는다.
- 기존 정적 계약만료·인정만료·계획갱신 템플릿은 위 원천 projection에 흡수한다.
- 기존 `신규수급자`, `신규직원`, `퇴사직원`, `수급자종료` 카드의 유지·보류
  여부는 사용자 결정 전까지 `UNKNOWN`이며 새 구현에서 임의 삭제·활성화하지 않는다.

## 11. 사회복지사 업무 달력

- 사회복지사 메뉴의 중심 화면은 상하단을 채우는 월 달력이다.
- 로그인 사용자 모두가 사회복지사를 선택해 그 사람의 담당 수급자 목록과
  방문일정을 조회할 수 있다.
- 방문일정에는 수급자 이름과 시간만 표시하며 수급자 상세 링크를 만들지 않는다.
- 사회복지사·수급자·달력월 조합당 방문일정은 최대 1건이다.
- 방문일정은 해당 사회복지사와 센터장(`ADMIN`)만 생성·수정·삭제할 수 있다.
- 월 달력의 날짜를 클릭하면 이전 주·선택 주·다음 주의 3주 확대화면을 열고,
  우클릭하면 같은 사회복지사·같은 달의 월 화면으로 돌아간다.
- 자동카드 마감은 실제 기한 날짜에 표시하며 달력에서 직접 완료하지 않는다.
- 연차는 본인과 센터장만 조회하고 작성자 본인만 생성·수정·삭제한다.
- 개인 할 일·개인 일정은 작성자 본인만 조회·생성·수정·완료·삭제한다. 센터장도
  조회할 수 없으며 본문을 감사로그에 남기지 않는다. 소유자는 요청값이 아니라
  로그인 세션에서 결정한다.

## 12. 수급자–요양보호사 계획일정

- 방문요양, 방문목욕, 일시재가, 병원동행, 바로돌봄 5종을 모두 사용한다.
- 로그인 사용자 모두가 전체 일정을 조회·생성·수정·삭제하고 계획 Excel을
  가져올 수 있으며 변경을 audit한다.
- 계획 Excel 원본 bytes·hash, 가져온 시각과 실행자를 일정의 현재값과 분리해
  보존한다.
- 한 계획일정의 수정 단위는 수급자, 서비스, 요양보호사, 날짜, 시작시각,
  종료시각이다.
- 방문요양과 방문목욕은 한 일정에 서로 다른 요양보호사 1명 또는 2명을
  허용한다. 나머지 세 서비스의 제공인원 상한은 이번 계약에서 새로 확정하지 않는다.
- 일시 대체근무는 일반 요양보호사 변경이며 별도 대체 상태를 만들지 않는다.
- 계획일정은 기존 요양보호사 배정, 계약, 인정에 대한 필수 FK나 저장차단에
  의존하지 않는다.
- 가져온 일정도 사람이 자유롭게 수정할 수 있고, 명확히 짝이 맞는 첫 태그
  반영이 다시 수정할 수 있으며, 이후 사람이 다시 수정할 수 있다.
- 일정 중복과 재직·서비스 자격 불일치를 경고할지 차단할지는 아직 결정하지
  않는다. 방문요양·방문목욕의 정상적인 2인 일정을 충돌로 간주하지 않는다.
- 실제 익명화 계획 Excel을 받기 전에는 열 이름·식별자·헤더 위치·중복행
  처리방법을 임의 확정하지 않는다.

## 13. 실제 태그 Excel과 계획시간 보정

로그인 사용자 모두가 태그 Excel을 가져올 수 있다.

태그와 계획의 자동 짝짓기는 같은 수급자·요양보호사·날짜이고 아래 시작시각
범위에 들어오는 계획일정이 **정확히 1건**일 때만 허용한다. 후보가 0건이거나
2건 이상이면 더 가까운 한 건을 임의 선택하지 않는다. 한 번의 가져오기에서
각 계획행과 각 태그행은 최대 한 번만 사용한다. 계획 시작시각은 이미 30분
단위라고 전제한다.

계획 시작시각을 `P`라 할 때 보정 시작시각은 다음과 같다.

| 태그 시작시각 | 보정 시작시각 |
|---|---|
| `P-59분` ~ `P-30분` | `P-30분` |
| `P-29분` ~ `P+29분` | `P` |
| `P+30분` ~ `P+59분` | `P+30분` |
| `P-60분` 이하 또는 `P+60분` 이상 | 자동수정하지 않음 |

- 서비스시간은 태그 종료시각에서 시작시각을 뺀 총 분을 30분 단위로 내림한다.
  예를 들어 180~209분은 180분, 210~239분은 210분이다.
- 30분 미만은 자동수정하지 않고, 480분을 초과하면 480분으로 제한한다.
- 보정 종료시각은 `보정 시작시각 + 보정 서비스시간`이다. 시작·종료는 한
  transaction에서 함께 바꾸고 둘 중 하나만 바꾸지 않는다.
- 종료 태그 없음, 계획만 있음, 태그만 있음, 1시간 이상 차이, 비정상 시간,
  후보 0건, 후보 2건 이상은 일정표에 사유를 늘어놓지 않고 `확인요망`만 표시한다.
- `계획만 있음`은 가져온 Excel의 포함 날짜 범위 안에서만 판정한다. `태그만 있음`은
  계획일정을 새로 만들지 않는다.
- 원본 Excel bytes와 hash, 가져온 시각, 원본 행번호·원시값, 연결된 계획행,
  적용 전·후 값과 가져오기를 실행한 계정을 보존한다. 자동반영 audit의 행위자는
  `SYSTEM/IMPORT`다.
- 같은 내용 hash의 파일은 중복 처리하지 않는다. 한 번 반영된 날짜는 이후
  수정된 파일에 다시 들어 있어도 건너뛰고, 여러 날짜가 섞인 파일은 새 날짜만
  처리한다.
- 태그 가져오기용 범용 백그라운드 업무큐나 플랫폼은 만들지 않는다.
- 실제 익명화 태그 Excel을 받기 전에는 열 이름·식별자·헤더 위치·다중 sheet
  처리방법을 임의 확정하지 않는다.

## 14. 실제 급여제공 기반 직원교체

- 실제 급여제공 그룹의 업무키는 수급자·서비스·날짜·시작시각·종료시각이다.
  방문요양과 방문목욕의 한 그룹에는 요양보호사 1명 또는 2명이 있을 수 있다.
- 태그 원본행 순서가 아니라 수급자·서비스별 실제 급여제공 그룹을 시간순으로
  놓고 직전 제공자 집합과 현재 제공자 집합을 비교한다. 서비스 공백이 있어도
  가장 최근 실제 제공 그룹이 직전 그룹이다.
- 첫 그룹은 교체가 아니다. 현재 집합에 새로 들어온 요양보호사마다 교체 1건이다.
  `A+B → A+C`는 C만 1건이고, 제거만 있거나 같은 집합의 순서만 바뀐 것은
  교체가 아니다.
- 일시 대체근무와 원래 직원의 복귀도 직전 집합에 없던 사람이 들어오면 교체다.
- 기준일은 새 요양보호사의 첫 실제 급여제공일(Day 1)이고 기한은 기준일 +13일이다.
- Day 14에 다시 교체되면 직전 미완료를 예외종결하고 새 교체를 만든다. Day 15
  이후 재교체에는 이 예외종결을 적용하지 않는다.
- 실제 급여제공 원천이 정정·무효화되면 교체 판정과 카드를 다시 계산한다.
- 직원교체 완료현황은 대상자와 완료/미완료만 보여준다. 상담일, 상담내용,
  미완료사유, 면제사유를 새 입력으로 만들지 않는다.

## 15. 계정·설정

- 센터장과 관리책임자는 같은 역할이며 시스템 역할명은 `ADMIN`으로 통일한다.
  사회복지사와 간호사 계정은 `USER`다.
- 최초 설치는 센터장 직원 DB 행과 `ADMIN` 계정을 함께 만들고 즉시 연결한다.
  설정의 계정관리에서는 이 기존 연결을 표시만 하고 임의 재연결하지 않는다.
- 센터장은 기존 직원 DB에서 아직 다른 계정과 연결되지 않은 사회복지사·간호사를
  선택해 `USER` 계정을 만들고 닉네임·PIN을 설정할 수 있다. 직원 한 명과 계정
  한 개를 1:1로 연결하며 중복 직원이나 중복 연결을 만들지 않는다.
- 센터장은 PIN 재발급, 계정 사용중지·재사용을 할 수 있다. PIN 변경·재발급은
  기존 세션을 무효화하고 PIN 평문·hash·lookup 값을 audit에 남기지 않는다.
- 유일한 `ADMIN` 계정은 사용중지할 수 없다.
- 센터장–직원 연결은 최초 연결 뒤 일반 재연결 기능으로 제공하지 않는다.
  실제 잘못 연결된 사례와 안전한 재연결 절차는 사용자 결정 전까지 확정하지 않는다.
- 센터 기본정보와 `센터 한마디`는 로그인 사용자 모두가 보고 센터장만 수정한다.
  감사로그 조회는 센터장 전용이다.
- 사용자별 범용 권한 편집기와 공통 기능용 `AccountPermission` 행을 만들지 않는다.

## 16. 파일함과 상세설계 보류

- 파일함은 탐색기처럼 폴더를 만들고 파일을 올리고 내려받고 이름을 바꾸고
  이동하는 기능을 제공한다.
- 로그 전용 영역을 제외한 일반 폴더·파일은 로그인 사용자 모두가 사용하며
  변경을 audit한다.
- 1차 범위는 휴지통과 복원을 포함하고 영구삭제·파일 버전관리·자동 정리(GC)는
  포함하지 않는다.
- 서버 경로 밖 접근과 symlink·junction·reparse point 우회는 차단한다. Excel
  가져오기 원본과 업무 감사로그는 일반 파일함 자료와 섞지 않는다.
- 본인부담금, OCR, 일반 입출력은 메뉴를 유지하되 현재 상세 재설계를 보류한다.

## 17. 교차영역 업무개념 freeze

이 절은 미래 테이블명 목록을 고정하지 않고 후속 영역이 소비할 **업무 의미**를
고정한다. `IDENTITY`는 정정 뒤에도 같은 대상을 뜻하는 뿌리,
`PERIOD_FACT`는 적용기간을 가진 사실, `REVISION`은 같은 대상의 명시적 버전,
`CURRENT_PROJECTION`은 원장에서 계산한 현재값이다. 실제
테이블·PK·FK 매핑과 제약은 04만 소유한다.

| 업무개념 | 의미 분류 | 정정 뒤 지속·대체 의미 | 후속 사용 |
|---|---|---|---|
| 직원 생애 | `IDENTITY` | 정정·재입사 뒤에도 같은 직원 identity 지속 | 태그 직원매칭·실제근무·방문 |
| 재직 | `PERIOD_FACT` | 재입사는 새 사실, 정정은 기존 사실을 보존하고 무효화·대체 | 재직 유효성·초기등록 |
| 직원 전화 정규화값 | `CURRENT_PROJECTION` | 원문·규칙버전으로 재계산하며 identity가 아님 | 태그 후보매칭 보조 가능, 실제 Excel 확인 전 확정 금지 |
| 일반 자격증 사실 | `IDENTITY` | 선택한 사실 ID는 보존하고 정정은 무효화·대체를 명시 | 서비스 제공자격의 선택 근거 |
| 서비스 제공자격 | `PERIOD_FACT` | 정정·기간변경은 대체 사실과 이력을 남김 | 일정 경고/차단 정책은 미결 |
| 수급자 생애 | `IDENTITY` | 계약·인정·연락처 정정 뒤에도 같은 수급자 identity 지속 | 계획·태그·파일 가져오기 |
| 인정 본번호 소유권 | `IDENTITY` | 한 수급자 1개·전역 소유권을 유지하며 일반 수정으로 교체하지 않음 | 인정 표시·태그 후보매칭 가능 |
| 인정·등급·혜택·승인금액 | `PERIOD_FACT` | 정정은 기존 기간사실을 보존하고 새 대체 사실을 만듦 | 완료현황·향후 금액영역 |
| 서비스계약 | `IDENTITY` | 종료 뒤 재이용은 새 계약 identity이며 과거 계약은 지속 | 계약만료 완료현황 |
| 서비스 종류 | `IDENTITY` | 확정 code 의미를 유지 | 계획·태그·직원교체 |
| 요양보호사 배정 | `PERIOD_FACT` | 기존 배정사실과 대체관계를 보존 | 새 일정 저장차단에는 사용하지 않음 |
| 사회복지사 담당연결 | `PERIOD_FACT` | 변경 전후 담당 이력을 보존 | 방문일정 대상 목록 |
| 독립 납부자 snapshot | `PERIOD_FACT` | 보호자와 독립된 유효기간 snapshot을 대체 이력으로 보존 | 상세설계가 보류된 본인부담금 영역 |

별도 업무 `REVISION` 구조를 새로 승인하지 않는다. `row_version`은
동시성 토큰이고 audit·무효화/대체는 변경근거이므로 위 네 업무개념 분류의
identity가 아니다. `CURRENT_PROJECTION`은 별도 사용자 승인 없이 후속 이력의
FK 대상이나 정본 식별자로 사용하지 않는다.

각 단계에서 사용하기 전에는 만들지 않는 연결점:

- 태그 event/execution FK
- 계획 Excel source row/group key
- 실제 service execution
- 본인부담금·billing run
- document/filebox/import 역참조 FK와 필수 의존
- OCR run/apply 역참조 FK와 필수 의존

## 18. 공통 API·UI·감사 요구

- 전체 일정, 계획·태그 Excel 가져오기, 수급자·직원 명단과 기본정보,
  수급자·직원 완료현황, 사회복지사 담당연결은 로그인 사용자 모두가 조회·변경한다.
  이 공통 기능에 별도
  `AccountPermission` 행을 요구하지 않는다.
- 모든 변경 API는 인증·CSRF와 적용 가능한 `row_version`을 검사한다. 민감정보,
  계정·설정, 방문일정, 연차, 개인 일정은 각 절의 더 강한 고정 권한을 적용한다.
- 업무 오류코드의 도메인 의미는 이 문서가, 공통 봉투·HTTP 상태는
  [05 §3](05_기술_보안_파일처리_아키텍처_v1.5.md#api-contract)가,
  화면 표시는 03이 소유한다.
- OpenAPI를 TypeScript 생성 타입의 기술 원본으로 사용한다.
- 생성 타입을 직접 수정하지 않는다.
- 목록 정렬은 마지막 PK까지 결정적이다.
- 이름 선택·목록 문맥·일정 popup의 UI 계약은
  [`03` §1.1·§7](03_UI_API_상호작용_계약_v1.2.md)을 따른다.
- legacy mapping은 API·OpenAPI·UI·검색·출력에서 제외한다.
- 생성·수정·삭제·완료취소·무효화·대체·기간변경·민감조회는 감사에 남긴다.
  단, 개인 할 일·개인 일정의 내용과 행위는 다른 사용자가 읽는 감사로그에
  남기지 않는다.
- 완료자와 완료시각은 감사에는 남겨도 수급자·직원 완료현황 목록에는 표시하지 않는다.
- 실제 개인정보를 테스트·fixture·문서에 사용하지 않는다.
