## 0. 적용 경계

이 문서는 현재 제품에서 사용자에게 보이는 화면, 공개 API 응답, 권한에 따른
노출과 상호작용을 정의한다. 기존 화면은 레이아웃 참고자료일 뿐 필드·필수값·
상태·권한의 정답이 아니다.

사이드바 메뉴와 각 메뉴의 화면 소속은 이 문서 §2가 소유한다. 업무 대상조건과
날짜 계산은 02, DB 불변조건은 04, 인증·파일·원본보존 구현은 05가 소유한다.
미결정인 동작은 임시 기본값으로 구현하지 않는다.

이 ERP는 공단 전산을 복제하지 않는다. 공단이 이미 검증하는 급여계획서 적용기간,
계약·인정 적합성 등을 UI가 다시 검증하거나 저장거부 조건으로 만들지 않는다.

## 1. 전역 UI 계약

### 1.1 프레임과 탐색

- 데스크톱 내부망 사용을 기준으로 기존 사이드바·상단바·작업영역 구조를 유지한다.
- 사이드바의 8개 메뉴는 삭제·추가하지 않는다.
- 직원·수급자 이름을 선택하면 목록 문맥을 잃지 않고 같은 작업영역에서 상세를
  연다. 우측 분할패널 또는 목록과 공존하는 상세영역을 사용한다.
- 뒤로가기·닫기 뒤 직전 검색어·필터·정렬·페이지를 복원한다.
- 데이터 없는 `수급자·요양보호사·사회복지사` 3종 공용 일정 팝업은 활성 계약이
  아니다. 실제 전체 일정과 사회복지사 업무 허브로 교체한다.
- 대시보드는 유지하고 `내할일` 영역만 제거한다. 대시보드에 사회복지사 달력
  이동링크를 새로 만들지 않는다.
- 목록 정렬은 마지막 내부 PK까지 결정적으로 표시한다.
- 저장 중 중복 제출을 막고 성공·실패·충돌 상태를 명확히 알린다.

### 1.2 입력 control

- 프로젝트 전체에서 완료 입력에 checkbox를 사용하지 않는다.
- 미완료는 `완료 처리`, 완료는 `완료 취소` 버튼으로 바꾼다.
- 예외는 기존 보호자 행의 `납부자로 지정` 선택 하나뿐이다.
- 반기평가는 완료 버튼 대신 실제 통보일 입력·무효화를 사용한다.
- 건강검진은 완료 버튼 대신 검진일 입력·비우기를 사용한다.
- 라벨에서 필수·선택을 정확히 구분한다.
- 서버 성공 전에 저장·완료처럼 표시하지 않는다.

### 1.3 오류와 충돌

- 서버 업무 오류코드와 필드 오류를 임의 문자열로 바꾸지 않는다.
- 409 `row_version` 충돌 시 입력을 보존하고 최신값 재조회·재적용 선택을 제공한다.
- 422 업무검증은 대상 행·기간·충돌 대상을 구조화하여 보여준다.
- legacy key·내부 mapping·민감 평문은 DOM·URL·다운로드에 노출하지 않는다.
- 일정 저장의 다음 판정은 사용자 결정 전까지 오류코드·경고·차단 중 어느 것도
  정답으로 고정하지 않는다.
  - 동일 요양보호사의 서로 다른 일정 겹침
  - 동일 수급자의 서로 다른 일정 겹침
  - 근무일의 재직·서비스자격 불일치
- 같은 수급자·서비스·날짜·시작·종료에 묶인 정상 2인 급여는 충돌이 아니다.
- 계약·인정·기존 `CareAssignment`는 일정 저장의 필수검사로 사용하지 않는다.

### 1.4 접근성

- 키보드만으로 목록·탭·대화상자·저장·취소·완료·완료취소를 조작할 수 있어야 한다.
- 오류·완료·주의·`확인요망`은 색상만으로 구분하지 않는다.
- 클릭 가능한 달력 날짜·일정·버튼에는 이름과 현재 상태가 있어야 한다.
- 우클릭으로 월간화면으로 돌아가는 동작은 키보드로도 실행할 수 있는 대체 control을
  함께 제공한다.

### 1.5 민감정보

- 주민등록번호는 `birth_date`에서 만든 `YYMMDD-*******`만 기본 표시한다.
- 관리자 reveal은 일반 상세와 분리된 버튼·경고·step-up 대화상자를 사용하며
  [`05` §5.5](05_기술_보안_파일처리_아키텍처_v1.5.md#resident-security)를 따른다.
- 평문 주민등록번호를 브라우저·TanStack Query·폼·DOM snapshot에 보존하지 않는다.
- reveal 응답은 대화상자를 닫거나 화면을 이탈하면 즉시 폐기한다.

### 1.6 고정 권한

다음 공동기능은 로그인 사용자 모두가 조회·수정한다. 변경요청은 CSRF를 검사하고
전후값·행위자·시각을 감사한다.

- 수급자·직원 명단과 일반 기본정보
- 수급자 5개·직원 6개 완료현황
- 전체 수급자·요양보호사 일정
- 공단 계획일정·태그 Excel 가져오기
- 사회복지사 담당 수급자 연결
- 일반 파일함의 폴더·파일

위 공동 API는 `AccountPermission`, `STAFF_VIEW/MANAGE`,
`RECIPIENT_VIEW/MANAGE` 부여행을 요구하지 않는다. 기존 permission 자료를
이 문서만으로 삭제하지는 않는다. 주민등록번호 reveal·정정 등 민감정보 명령은
기존 전용 보안계약을 유지한다.

예외 권한은 다음과 같다.

| 항목 | 조회 | 생성·수정·삭제·완료 |
|---|---|---|
| 사회복지사 방문일정 | 로그인 사용자 모두가 사회복지사를 선택해 조회 | 해당 사회복지사와 `ADMIN` |
| 사회복지사 연차 | 작성자 본인과 `ADMIN` | 작성자 본인 |
| 개인 할 일·개인 일정 | 작성자 본인만 | 작성자 본인만 |
| 센터 기본정보·센터 한마디 | 로그인 사용자 모두 | `ADMIN` |
| 계정관리·감사·시스템·가져오기 로그 | `ADMIN` | 계약에서 허용한 `ADMIN` 명령만 |

개인 할 일·개인 일정의 소유자는 요청값이 아니라 로그인 계정으로 서버가 정한다.
다른 USER와 ADMIN 응답에서 모두 제외하고, 센터장용 `AuditEvent`에도 사건이나
내용을 남기지 않는다.

## 2. 메뉴별 화면

| 메뉴 | 유지·개정할 화면 | 제외·DEFER |
|---|---|---|
| 대시보드 | 기존 대시보드, 원천자료에서 계산한 자동 업무카드 | `localStorage` 내할일, 단계형 카드, 사회복지사 달력 링크 |
| 수급자 | 목록·기본·보호자·납부자·인정·등급·혜택·승인금액·계약, 5개 완료현황, 전체 일정 연결 | 인정전환 일괄 UI, 계약연결형 급여계획서 |
| 직원 | 목록·기본수정·재직·자격, 6개 완료현황 | 재직 중 직종변경, 임의 업무역할 편집, 상담 상세내용 |
| 사회복지사 | 사회복지사 선택, 담당 수급자, 전면 달력, 방문·마감·연차·개인일정 | 간호사 별도 탭·별도 배정, 외부 앱 연동 |
| 본인부담금 | 메뉴와 현재 화면 유지 | 이번 재정렬의 상세기능은 `DEFER / OUT-OF-SCOPE` |
| 입출력 | 메뉴와 현재 화면 유지 | 일반 입출력·OCR 상세기능은 `DEFER / OUT-OF-SCOPE` |
| 파일함 | 탐색기형 폴더·파일 공동관리, 휴지통·복원 | OCR, 영구삭제, 파일버전, GC |
| 설정 | 계정관리·센터정보·센터 한마디·감사로그 | 임의 권한편집기, 일반 사용자의 로그 조회 |

간호사는 표시 직군만 다르고 사회복지사와 동일하게 취급한다. 사회복지사 메뉴에
간호사 전용 탭·별도 담당배정·별도 권한을 만들지 않는다.

## 3. 직원 화면

<a id="ui-staff-core"></a>

### 3.1 직원 목록

표시:

- 이름
- 재직번호
- 현재 재직상태
- 현재 직종
- 마스킹된 연락처

휴대전화는 `010-****-5678`처럼 마지막 4자리만 남긴다. 다른 전화도 가입자번호
마지막 4자리 외 숫자는 마스킹한다. 검색은 이름·재직번호·전화 정규화 projection을
사용한다. legacy 직원키·평문 주민등록번호·구 시스템 별칭은 표시·검색하지 않는다.

<a id="ui-staff-sensitive"></a>

### 3.2 직원 기본정보

직원 상세는 수급자 상세와 같은 목록+상세 구조와 기본 디자인을 사용한다.
로그인 사용자 모두가 일반 기본정보를 수정하고 변경로그를 남긴다.

| 필드 | 상태 | 비고 |
|---|---|---|
| 이름 | 필수 | 직원 본체 |
| 주민등록번호 | 신규 일반직원 필수 | 기존 bootstrap 직원은 미등록 허용 |
| 주소 | 선택 | 일반 수정 가능 |
| 전화번호 | 선택 | 화면용 원문 저장 |
| 닉네임 | 선택 | 계정 표시명과 혼동하지 않도록 라벨 분리 |
| 메모 | 선택 | 자유문자 |

신규 입력은 서버의 달력·세기·성별 오류를 해당 필드에 표시한다. 클라이언트가
별도 checksum 규칙을 추가하지 않는다. 저장 뒤 평문 주민등록번호를 폼 default나
재조회 응답으로 돌려주지 않는다.

일반 수정화면에는 주민등록번호 input을 두지 않는다. 마스크는 조회용이며 빈 값
저장으로 번호를 삭제·교체하지 않는다. 별도 HIGH 정정 명령 없이 관리자도 일반
수정화면에서 번호를 바꾸지 않는다.

<a id="ui-staff-employment"></a>

### 3.3 재직·직종

- 재직기간 목록, 입사·퇴사·재입사를 제공한다.
- 재입사는 기존 직원에 새 재직기간을 추가한다.
- 재직번호는 저장 transaction에서 발급되며 사용자가 입력하지 않는다.
- 재직 중 직종변경 UI를 만들지 않는다.
- 직종이 바뀌면 기존 재직을 퇴사 처리하고 새 직종으로 재입사한다.
- 기존 업무역할·직종 이력은 조회할 수 있으나 임의 생성·교체 control을 만들지 않는다.

<a id="ui-staff-qualifications"></a>

### 3.4 자격증·서비스 제공자격

`자격증`과 `서비스 제공자격`은 별도 목록으로 유지한다.

- 자격증은 자격종류·자격번호·발급일을 관리한다.
- 서비스 제공자격은 재직기간·서비스종류·시작일·선택 종료일을 관리한다.
- 자격증과 제공자격은 서로를 자동 생성·종료하지 않는다.
- 기존 안정 ID와 이력을 유지하되 일반 화면에 내부 ID를 노출하지 않는다.
- 일정의 재직·자격 불일치를 경고할지 저장차단할지는 결정 전 고정하지 않는다.

<a id="ui-staff-training"></a>

### 3.5 직원 6개 완료현황

분류 이름은 다음 여섯 개로 고정한다.

1. 보수교육
2. 직원상담
3. 인권교육
4. 연간교육
5. 건강검진
6. 신규교육

분류와 대상기간을 선택하면 대상자 이름·완료/미완료만 중심으로 보여준다.
발생이유·완료자·완료시각·상세화면 링크·상담내용·사유를 표시하지 않는다.

| 분류 | 화면 대상 | 완료 UI |
|---|---|---|
| 보수교육 | 현재 재직 요양보호사 중 대상연도/출생연도 홀짝이 같고 `대상연도-최초 요양보호사 자격 취득연도 > 2` | 완료 처리·완료 취소 버튼. 자격일 없음은 `확인요망` |
| 직원상담 | 선택 분기 전체를 재직한 요양보호사. 분기 첫날 입사·말일 퇴사 포함 | 완료 처리·완료 취소 버튼. 처음에는 현재 분기 |
| 인권교육 | 선택 반기 말일 재직자. 말일 퇴사 포함 | 완료 처리·완료 취소 버튼 |
| 연간교육 | 선택 연도 12월 31일 재직자. 당일 퇴사 포함 | 5개 과목 각각 버튼으로 완료·취소하며 전체 완료를 계산 |
| 건강검진 | 해당 연도 신규입사자는 중도퇴사해도 포함, 기존 직원은 12월 31일 재직(당일 퇴사 포함) | 검진일 입력·비우기만 사용 |
| 신규교육 | 입사·재입사 재직기간마다 1건 | 완료 처리·완료 취소 버튼. 퇴사 뒤에도 이력 유지 |

같은 대상기간의 재입사는 인권교육·연간교육 완료를 이어 쓰되 신규교육은 새
재직기간 건을 만든다. 건강검진은 검진일이 입사일보다 정확히 1 calendar year를
초과하여 오래됐을 때만 주의 표시한다. 검진유형·결과메모·면제상태를 활성 UI에
두지 않는다.

<a id="ui-staff-health"></a>

### 3.6 건강검진 입력

- 검진일 하나만 입력한다.
- 검진일이 있으면 완료, 비우면 미완료다.
- `COMPLETE/INCOMPLETE/EXEMPT` 선택기·검진유형·결과메모·면제사유를 만들지 않는다.

### 3.7 직원상담 입력

- 현재 분기를 기본으로 열고 다른 연도·분기를 선택할 수 있다.
- 대상자와 완료 여부만 관리한다.
- 상담일·상담내용·미완료사유·면제사유 입력을 만들지 않는다.
- 실제 급여제공 순서에서 생기는 직원교체 상담과 화면·대상판정을 섞지 않는다.

## 4. 수급자 화면

### 4.1 목록·기본정보

목록은 이름·수급자번호·생년월일·성별·현재 계약 서비스 요약을 표시한다.
필터 순서는 이용중(`ACTIVE`)·전체(`ALL`)·계약종료(`ENDED`)·대기중(`WAITING`)이며
최초 진입은 `ACTIVE`, API 생략 기본값은 `ALL`이다. 상태는 계약기간에서 추론하지
않는 수동 태그다.

기본정보는 이름·생년월일·성별·상태·우편번호·주소·자택전화·휴대전화를 사용한다.
로그인 사용자 모두가 일반 기본정보를 조회·수정하고 감사한다. legacy key·구
등록번호는 표시·검색·출력하지 않는다.

### 4.2 보호자·납부자

- 보호자는 수급자당 0명 이상이며 이름만 필수다.
- 전화·주소·관계는 선택이다.
- 대표 보호자 0명을 허용한다.
- 기존 보호자 행의 `납부자로 지정` checkbox는 프로젝트 전체 checkbox 금지의
  유일한 예외다.
- 납부자 지정 뒤에도 납부 정보는 업무시점 snapshot이며 보호자 수정으로 과거
  납부자료를 자동 변경하지 않는다.
- 복잡한 대표보호자·납부자 기간형 이력 편집 UI는 `DEFER`다.

### 4.3 인정·등급

- 인정번호 입력은 `L + 숫자 10자리`와 suffix 제거를 안내한다.
- 인정 본번호·인정기간·등급기간을 표 또는 타임라인으로 표시한다.
- 현재 유효 인정 본번호를 수급자 기본 화면에 실제 자료로 표시한다.
- 인정 발급일은 필수 입력으로 만들지 않는다.
- 등급 선택지는 `1`~`5`를 사용한다.
- 인정전환 preview·최종확인·일괄적용 UI를 만들지 않는다.
- 인정·등급은 일반 등록·수정·무효화 흐름으로 관리한다.

### 4.4 혜택·승인금액

- 기존 혜택 6종, 기간, 무효화·대체 이력을 유지한다.
- 지자체 승인금액은 별도 목록에서 원 단위 금액·시작일·종료일을 관리한다.
- 자료 없음은 빈 상태이며 임의 기본행을 자동생성하지 않는다.

### 4.5 수급자 5개 완료현황

분류 이름은 `상담반영·반기평가·서류미비·인정만료·계약만료`로 고정한다.
분류와 연도·월 등 해당 대상기간을 선택하면 대상자 이름과 완료 여부만 보여준다.

| 분류 | 대상 | 완료 UI |
|---|---|---|
| 상담반영 | 선택 연도 연 1회, 그해 중도 계약종료자는 제외 | 완료 처리·완료 취소 버튼 |
| 반기평가 | 유효 통보일이 없거나 최신 통보일 기준 다음 작성시점이 온 수급자 | 실제 통보일 입력·무효화. 별도 완료 버튼·boolean 없음 |
| 서류미비 | 선택 월에 수급자–요양보호사 서비스 일정이 하나라도 있는 모든 수급자 | 완료 처리·완료 취소 버튼 |
| 인정만료 | 현재 적용 인정의 종료일 D-100 구간 대상 | 완료 처리·완료 취소 버튼 |
| 계약만료 | 현재 적용 계약의 종료일 D-45 구간 대상 | 완료 처리·완료 취소 버튼 |

서류미비의 일정은 사회복지사 방문·연차·개인일정이 아니라 §6의 수급자–요양보호사
서비스 일정이다. S4 일정 원장이 생기기 전에는 가짜 일정이나 다른 달력자료로
대상자를 채우지 않는다.

반기평가 권장기한은 `min(최신 유효 통보일에서 6개월이 되는 달의 말일,
현재 인정만료일, 현재 계약만료일)`이며 D-45에 알린다. 통보일이 없으면 임의
기한을 만들지 않고 미완료 목록과 카드에는 표시하되 달력에는 넣지 않는다.
계획적용 시작·종료 텍스트는 검증·저장거부에 사용하지 않는다.

## 5. 계약 화면

### 5.1 서비스와 활성 필드

다섯 서비스 `방문요양·방문목욕·일시재가·병원동행·바로돌봄`을 모두 사용한다.

| 필드 | 상태 |
|---|---|
| 서비스 종류 | 필수 |
| 계약 시작일 | 필수 |
| 계약 종료일 | 선택 |
| 종료사유 | 선택 자유문자 |

기존 DB 값은 이 UI 개정만으로 물리 삭제하지 않는다.

### 5.2 계약 종료와 수급자 상태

- 계약 종료는 종료일과 선택 종료사유를 저장하는 동작이다.

- 종료된 계약을 재활성화하지 않고 필요하면 새 계약을 등록한다.

### 5.3 제거된 화면

- 인정전환 preview·hash·최종확인·apply
- 계약에 연결된 W2 급여계획서 입력
- 계획적용기간의 계약·인정기간 검증과 저장거부

기존 인정·등급·계약·계획서 행은 별도 안전폐기 절차 전까지 보존한다.

## 6. 전체 수급자·요양보호사 일정

### 6.1 일정 화면

- 일정의 수정 단위는 수급자·서비스종류·요양보호사·날짜·시작·종료다.
- 로그인 사용자 모두가 조회·생성·수정·삭제한다.
- 모든 변경은 변경 전후값·행위자·시각을 감사한다.
- 다섯 서비스를 모두 표시한다.
- 방문요양·방문목욕은 같은 수급자·서비스·날짜·시작·종료 묶음에 서로 다른
  요양보호사 1명 또는 2명을 허용한다.
- 다른 세 서비스의 제공자 수에는 이번 결정으로 새 저장제약을 만들지 않는다.
- 일시 대체근무는 요양보호사를 바꾸는 일반 수정이다. 별도 대체 상태·테이블을
  만들지 않는다.
- 계획일정의 요양보호사 변경만으로 직원교체 상담을 만들지 않는다.
- 기존 장기 `CareAssignment`는 자료만 보존하며 새 일정의 필수 FK·화면 전제로
  사용하지 않는다.

### 6.2 공단 계획일정 Excel

- 로그인 사용자 모두가 가져올 수 있다.
- 원본·가져온 계정·처리시각·생성/변경 결과를 확인할 수 있다.
- 가져온 뒤 사람의 일정 수정·삭제를 허용한다.
- 실제 가명 Excel 표본이 오기 전에는 시트명·열 이름·수급자·직원 식별값과
  parser를 추측해 만들지 않는다.
- 이름만 비슷한 수급자·직원을 자동 연결하지 않는다.

### 6.3 넣지 않는 일정 control

- 확정월 잠금·해제·재확정
- 일괄취소 preview·최종확인
- WARNING 확인자·확인시각
- 계약·인정·장기배정을 통한 저장차단
- 데이터 없는 3종 공용 일정 팝업

## 7. 대시보드 업무카드

- 기존 대시보드 화면을 유지한다.
- 브라우저 `localStorage`의 `내할일` 영역만 제거한다.
- 사회복지사 달력 이동링크를 추가하지 않는다.
- 자동카드는 원천자료와 완료자료에서 계산한다.
- 카드에는 대상자명·업무명·마감일 또는 D-day·완료만 표시한다.
- 발생이유·담당자·단계·첨부·복수 상태·완료자·완료시각·상세링크를 넣지 않는다.
- 카드 전용 범용 원장이나 작업큐를 만들지 않는다.

활성 카드 종류:

1. 계약만료 — 계약 종료일 D-45
2. 인정만료 — 인정 종료일 D-100
3. 반기평가 — 최신 통보일·인정/계약 cap으로 계산한 기한 D-45
4. 직원교체 — 실제 급여제공 순서에서 계산한 첫 제공일 +13일

계약만료·인정만료·직원교체 카드는 같은 완료원장에 연결된 `완료`·`완료 취소`
버튼을 사용한다. 반기평가 카드는 완료 toggle 대신 실제 통보일 입력·무효화만
사용한다. 완료 checkbox는 사용하지 않는다.

기한이 지나도 미완료면 남고 완료하면 활성 목록에서 빠진다. 이력과 달력 완료표시는
보존한다. `신규수급자·신규직원·퇴사직원·수급자종료` 카드는 유지 여부 결정 전
새로 구현하거나 되살리지 않는다.

## 8. 사회복지사 업무 허브

### 8.1 담당과 방문일정

- 사회복지사를 선택하면 모든 로그인 사용자가 그 사람의 담당 수급자와 방문일정을
  조회한다.
- 로그인 사용자 모두가 누구의 담당 연결이든 생성·변경·삭제하고 감사한다.
- 방문일정은 해당 사회복지사와 `ADMIN`만 생성·수정·삭제한다.
- 같은 사회복지사·수급자·달력월에는 방문일정을 최대 1건만 둔다.
- 방문일정에는 수급자명과 시간만 표시하며 수급자 상세화면 링크를 만들지 않는다.

### 8.2 전면 달력

- 기본은 한 달 보기이며 사회복지사 화면의 남는 가로·세로 작업영역을 채운다.
- 날짜 칸을 선택하면 선택 주를 중심으로 전주·선택 주·다음 주의 3주 보기로
  확대한다.
- 3주 보기에서 달력 영역을 우클릭하면 월간화면으로 돌아간다.
- 키보드 사용자를 위한 `월간으로 돌아가기` control도 제공한다.
- 확대·복귀 뒤에도 선택한 사회복지사와 보고 있던 달을 유지한다.
- 자동 마감은 업무카드의 실제 기한 날짜에 표시한다.
- 달력에서는 자동 마감을 직접 완료·취소하지 않고 같은 원천 완료값을 읽는다.

### 8.3 연차와 개인일정

- 연차는 작성자 본인과 `ADMIN`만 조회한다.
- 연차 생성·수정·삭제는 작성자 본인만 한다.
- 다른 사회복지사는 연차 응답을 받지 않는다.
- 개인 할 일·개인 일정은 작성자만 조회·생성·수정·완료·삭제한다.
- 개인 항목은 다른 USER·ADMIN의 API 응답과 감사로그에서 사건·내용 모두 제외한다.

## 9. 태그 Excel과 일정 보정

### 9.1 가져오기와 표시

- 로그인 사용자 모두가 가능한 매일 전날 태그 Excel을 가져온다.
- 자동수정 조건을 모두 통과하지 못하면 일정을 바꾸지 않고 달력에는 세부사유 없이
  `확인요망`만 표시한다.
- 종료 태그 없음, 계획만 있음, 태그만 있음, 범위초과, 30분 미만, 비정상값,
  후보 0개·2개 이상을 같은 `확인요망`으로 표시한다.
- `계획만 있음`은 Excel이 실제 포함한 날짜 범위에서만 판정한다.
- `태그만 있음`은 가짜 계획일정을 만들지 않고 해당 날짜의 예외표시만 만든다.

### 9.2 자동보정

계획 시작을 `P`라 할 때:

| 태그 시작 | 보정 시작 |
|---|---|
| `P-59분` ~ `P-30분` | `P-30분` |
| `P-29분` ~ `P+29분` | `P` |
| `P+30분` ~ `P+59분` | `P+30분` |
| `P-60분` 이하 또는 `P+60분` 이상 | 자동수정 없음 |

- 수급자·요양보호사·날짜와 위 범위를 통과한 후보가 정확히 1개일 때만 짝을 맺는다.
- 더 가까운 후보가 있어도 후보가 둘 이상이면 자동선택하지 않는다.
- 한 번의 가져오기에서 계획일정과 태그행을 각각 한 번만 사용한다.
- 원본 서비스시간은 `태그 종료-태그 시작`이다.
- `min(480, floor(원본 분 / 30) × 30)`을 사용하며 30분 미만은 수정하지 않는다.
- 종료는 `보정 시작+확정 서비스시간`이다.
- 시작·종료는 한 transaction에서 함께 바꾸고 한쪽만 바꾸지 않는다.

### 9.3 원본·수동수정·재가져오기

- 원본 Excel bytes·콘텐츠 hash·가져온 시각·행위자를 변경 불가로 보존한다.
- 원본행 번호와 가공 전 수급자·요양보호사·날짜·시작·종료를 보존한다.
- 자동수정 전후 일정과 원본행 연결을 감사한다.
- 파일명이 달라도 콘텐츠 hash가 같으면 같은 원본이다.
- 그 날짜에 아직 태그를 적용하지 않았다면 첫 정상 import가 사람이 고친 일정도
  보정할 수 있다.
- 첫 태그 반영 뒤 사람이 다시 자유롭게 고칠 수 있다.
- 날짜별 적용이 끝난 날짜는 수정된 Excel로 다시 들어와도 건너뛴다.
- 한 파일에 처리된 날짜와 새 날짜가 섞이면 새 날짜만 처리한다.

5분 최적화·1,799초·수가행 비교·여러 후보 최근접 선택은 활성 계약이 아니다.

### 9.4 직원교체 완료현황

- 수급자·서비스·날짜·시작·종료가 같은 실제 제공행을 한 묶음으로 본다.
- 시간순 직전 묶음과 현재 묶음의 요양보호사 집합차이에서 새로 들어온 사람마다
  1건을 만든다. `A+B → A+C`는 C만 대상이다.
- 첫 실제 제공 묶음은 교체가 아니며 하루 대체와 복귀도 같은 집합차이로 판정한다.
- 새 제공자의 첫 실제 제공일이 Day 1이고 기한은 +13일이다.
- Day 14 재교체는 미완료 앞 건을 예외종결하고 새 건을 만든다.
- 실제 제공 정정·무효화 뒤 대상 여부를 다시 계산한다.
- 상담일·내용·사유 없이 대상자와 완료·완료취소만 표시한다.

## 10. 파일함·설정·DEFER 화면

### 10.1 파일함

- 지정된 파일함 루트 안에서 폴더 보기·생성, 업로드, 열기/다운로드, 이름변경,
  이동, 휴지통, 복원을 제공한다.
- 로그인 사용자 모두가 공동 조회·수정하고 변경로그를 남긴다.
- 삭제는 휴지통 이동이며 모든 로그인 사용자가 복원한다.
- 영구삭제·파일버전·자동보존기간·GC control은 1차 범위에 없다.
- 감사·시스템·가져오기 로그와 import 원본은 일반 파일함에 표시하지 않는다.

### 10.2 설정

- `ADMIN`은 USER 계정 생성, 사회복지사·간호사 직원 1:1 연결, 닉네임,
  PIN 생성·재생성, 사용중지·해제를 관리한다.
- PIN 재생성·사용중지는 기존 세션을 끝낸다.
- 유일한 ADMIN은 사용중지할 수 없다.
- 기본 ADMIN의 직원 연결은 표시만 하고 실제 오연결 사례 전에는 재연결하지 않는다.
- 센터정보와 센터 한마디는 모든 로그인 사용자에게 필요한 범위를 표시하고
  `ADMIN`만 수정한다.
- 감사·시스템·가져오기 로그는 설정의 `ADMIN` 전용 화면에서 조회한다.
- PIN 원문·hash·lookup 값은 화면과 감사로그에 표시하지 않는다.

### 10.3 DEFER / OUT-OF-SCOPE

- 본인부담금·일반 입출력·OCR은 메뉴를 유지하되 이번 재정렬에서 삭제하거나
  새 의미를 결정하지 않는다.
- 외부 WorkCadence 앱·인증·동기화·캐시·변경피드는 만들지 않는다.

## 11. OpenAPI 소비·DOM 계약

- 생성 OpenAPI 타입이 폼과 응답 타입의 기술 원본이며 직접수정하지 않는다.
- 선택값은 UI·OpenAPI·DB nullability가 일치해야 한다.
- 공통 오류 봉투·HTTP 상태·안정 코드는
  [05 §3](05_기술_보안_파일처리_아키텍처_v1.5.md#api-contract)가 소유한다.
- UI는 `field_errors`를 입력 옆에, 충돌 대상·기간·현재 version은 오류 요약에
  표시한다.
- 409에서는 사용자 입력을 보존하고 서버 최신값과 필드별 차이를 보여준다.
- forbidden 필드는 hidden input·fixture·mock 응답에도 두지 않는다.
- 개인일정 응답 model은 요청 계정 소유행만 반환한다. ADMIN용 응답이나 감사조회
  model에 개인일정 사건·내용을 넣지 않는다.
- 공동기능 테스트는 `AccountPermission` 부여행이 없는 USER도 성공해야 한다.
- 직원·수급자 목록→이름 선택→다른 이름 선택→뒤로가기에서 목록 문맥을 검증한다.
- 완료 control에 checkbox가 없고 반기평가·건강검진 예외 입력이 정확한지 검증한다.
- 사회복지사 달력은 전면영역, 월 1건, 3주 확대, 우클릭·키보드 복귀, 자동마감
  직접완료 금지, 개인일정 완전 비노출을 실제 API 응답과 DOM에서 검증한다.
- 전체 일정은 5개 서비스 CRUD, 방문요양·방문목욕 1/2인, 대체근무 일반수정,
  감사 전후값을 검증한다.
- 태그는 후보 0/1/2개, 정확한 ±60 경계, 30~480분, 원자수정, 날짜별 재import
  건너뛰기와 `확인요망`을 검증한다.
- 파일함은 루트 탈출 차단·휴지통·복원·영구삭제 API 부재를 검증한다.
- 민감 reveal은 POST·CSRF·현재 PIN step-up, no-store, 성공 1회당 access event
  1건과 dialog 종료 뒤 평문 DOM 부재를 검증한다.
